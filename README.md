# Peak Monk — Jun

An autoresearch laboratory for an original mountain monk character model. Work in progress: multiple text-adapter pilots have been trained and rejected; no accepted release checkpoint yet.

The project learns character behavior in weights, using original synthetic conversations with documented historical and fictional influences. All computation must fit the user's Apple M2 Mac with 8 GB memory. Text experiments use quantized Qwen models. Native full-duplex speech uses a custom Moshi MLX training path. Actual quantized native inference and adapter training now run on this Mac. Three trained speech adapters fail the character checks; they are experimental artifacts, not accepted releases.

The first speech experiments cache a frozen temporal prefix, unload its weights, and train only a suffix and text head with joint text/audio supervision. The split matches the full calculation's loss and gradients on the implementation test. The first complete 24-second native baseline generated in 22.48 seconds, with 5.17 GB peak MLX allocation. Separate CPU decoding took 5.94 seconds, and unprompted ASR recovered the spoken greeting and Moshi name. These separate timings do not establish a real-time end-to-end application. Pinning memory at the device-recommended wired limit fixed a severe slowdown seen with the default zero limit. Stock Kokoro voices provide synthetic training material; their output is never presented as the trained character's speech.

Speech-run01 completed 160 updates in 259 seconds, peaking at 3.10 GB MLX allocation. Frozen validation loss fell from 2.616 to 2.055. Loading its exported adapter into the full model produced exactly the same episode loss as the cached suffix (absolute difference 0). Native generation nevertheless failed to introduce Jun. Numerical equivalence and falling loss do not establish character or voice quality. Six baseline probes have decoded audio and unprompted ASR audits; their aggregate model-only generation real-time factor is 0.969. The fixed interruption probes did not establish clear pre-existing speech overlap, so interruption performance remains unproven.

Historical text experiments use the original MLX loss. A discovered padding-boundary issue is corrected in `scripts/assistant_objective.py`; new runs use `assistant_eos_v2` and a fresh baseline. Loss numbers from these versions are not comparable. Raw generated conversations, not lower loss alone, determine whether a checkpoint passes.

See `program.md`, `character/core.md`, and `sources/manifest.json`. Model files, adapters and the Python environment are local ignored artifacts; research code, data and measured results are versioned. Never commit credentials.

Jun speaks as a human monk within the character. The human_character_v2 rubric replaces the earlier mistaken disclosure requirement; historical results retain their original rubric. New supervision removes model/fiction explanations from Jun's replies, and longer dialogue probes test persistence under pressure. The program documents provenance outside the character conversation.

The small authored corpus is a current quality limitation. Early loss improvements have not yielded an accepted character checkpoint. Rejected teacher simulations and interrupted/failed training runs are retained for inspection. Fifty original speech conversations (48 train, 2 validation; 19.1 minutes of timeline) plus nine corrected human-character conversations have fresh-instance Mimi codes after a reset-contamination bug was detected and corrected. These codes are prepared training inputs, not a trained voice.

Full-conversation experiments train every assistant reply while masking caller words and formatting. Frozen validation still measures only the last reply, so evaluation CE stays comparable. Run15 reached 14/20 acceptable development cases at step600, but failed speaker memory, resistance to becoming an assistant, and personal history; later checkpoints regressed. Recommended Qwen sampling did not repair the main failures. Run16 resumes that experimental checkpoint with adapters in all 36 blocks and the tied embedding, plus broader relationship supervision. Its corpus contains 214 distinct texts and 742 assistant replies; 24 texts are variants of three retention templates, not independent authored designs. Weighting produces 451 records. Run16 finished in 20.1 minutes with 4.73 GB peak MLX allocation. Its final CE was 2.8086, but teacher history, perception and supernatural drift still failed. All captured checkpoints were rejected. The Qwen3.5 local teacher pilots were rejected for grounding failures; none of their generated conversations entered training. No final or pressure holdout has been run.

The current native experiment, speech-run06, adapts all 32 temporal blocks and the text head (6,318,080 parameters). It uses 16-frame gradient windows, complete carried forward attention context, and an optimizer state saved to disk between updates. This intentionally truncates gradients across window boundaries. A two-update probe on the longest 452-frame episode completed in 67.29 seconds with 5.48 GB peak MLX allocation. The 160-update character experiment is running; the feasibility probe establishes memory fit, not character quality. Runs04 and05 were not launched because their memory gates failed.

A verified Qwen3-4B-Base MLX quantization is ready for text run17. It uses simple ChatML without a persona system prompt. Its fresh baseline and character training remain pending while native training occupies the GPU. This follows Zero's base-model direction within the Mac's memory limit; our corpus and training recipe are much smaller than Zero's and are not a reproduction.
